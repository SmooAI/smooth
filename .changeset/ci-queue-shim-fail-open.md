`th ci-queue` shims fail open, and Big Smooth no longer downgrades `th` (th-35d0d0). On 2026-09-28 the desktop app, relaunching after a reboot, repointed `~/.local/bin/th` from Homebrew's th 0.58.0 to its bundled 0.54.0, which has no `ci-queue`. The v1 shims ran `exec th ci-queue run …` whenever any `th` was on PATH, so every heavy cargo, xcodebuild and gradle run on the machine failed with "unrecognized subcommand" for two hours. Shims are now v2. Before queueing, a shim probes `th ci-queue run --help`, first on the `th` that installed it (for a Homebrew install, `<prefix>/bin/th` and then the keg), then on PATH's `th`. It queues through the first one that answers. If none can, it prints one warning line and runs the tool unqueued with the tool's own exit status. `th ci-queue shim install` upgrades v1 shims in place, and `shim status` flags outdated ones. The desktop app repoints an existing `th` symlink only when the link points into an app bundle (or nowhere) and the `th` there is not newer than the bundled one. It leaves a link to Homebrew's or a dev build's `th` alone, and logs every decision to `~/.smooth/desktop.log`. The `ci-queue` help text no longer says jobs run at background QoS; `nice` has been the default since 0.58.
