`smoo work` (alias `smoo projects`) — CLI parity for the Smoo Projects product (SMOODEV-3038). New command groups: `smoo work projects` (list / show / create / update / archive — archive keeps history), `smoo work items` (list with every server filter — `--project SMOODEV --status open --assignee me` incl. `--support-ticket` / `--sprint` / `--release` — plus show / create / update / `transition <id> done` / rm), `smoo work sprints` (list / show / create / start / complete `--rollover-to`), `smoo work releases` (list / create / release), `smoo work links` (list / link `--file|--url|--item` / unlink / `for-file` reverse lookup), and `smoo work jira` (`import [--full]` to trigger the Temporal pull, `status` rendering `metadata.workItemsSync` — state / watermark / error — human-readably). Projects resolve by KEY anywhere an id is expected; `--assignee me` resolves through the session's email. `update` mirrors the server's set-vs-clear PATCH contract exactly: only flagged fields are sent, and every nullable field has a `--clear-*` twin that sends an explicit null. Priorities render as their 0–4 number plus label; statuses and states carry glyphs that survive `NO_COLOR`.
