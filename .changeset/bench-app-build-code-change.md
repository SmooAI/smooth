SMOODEV-4125: `smooth-bench agentic` gains two suites that check whether the code a model writes actually works. `app-build-scenarios.toml` has the agent build a Vite + React todo app with a stats dashboard from an empty directory; the harness then installs it, builds it, runs its tests and boots it headlessly. `code-change-scenarios.toml` seeds small repos and asks for a feature, a bug fix and a behavior-preserving refactor; held-out tests and a diff-scope check run afterwards. Hybrid checks gain `commands`, `serve`, `scope` and `scored`, and scenarios gain `fixture` and `holdout`. A scored judge rates requirements, correctness, code quality, scope discipline and process from 1 to 5 against a JSON schema, and the harness combines those ratings with the objective checks into a 0–100 quality score. The score appears on the scoreboard alongside token counts. `--model <model>@<provider>` routes one model through a `~/.smooth/providers.json` provider, which is how `claude-haiku-5-5` is benched, since the gateway does not serve it. `scripts/the-line/merge-model-scores.sh` adds newly benched models to the published board instead of replacing it. The daemon now reads `SMOOTH_NARC_JUDGE_URL` and `SMOOTH_NARC_JUDGE_KEY` (both must be set) to give Narc's judge its own endpoint. A direct route uses them to keep the judge on the gateway, so the safety layer is the same for every benched model.
